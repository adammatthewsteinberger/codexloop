# ADR 0006 — Generated OpenAI REST surface

## Status

Accepted

## Context

claudeloop's REST-parity milestone transplants almost unchanged: its
introspection technique walks a *class* tree of `cached_property` descriptors,
which is generic Python reflection, not anything vendor-specific. Pointing the
same mechanism at `openai.resources` works the same way, needs no credentials
at import time, and supports the same drift gate — so this milestone was
locked in from the start rather than treated as conditional.

## Decision

`codexloop api` is generated by walking the class tree under
`openai.resources`, binding each leaf's path and scalar parameters to typed
Typer options (request bodies go to `--json` / `--json-file`), with `--raw` /
`--stream` selecting the SDK's raw/streaming response variants and list
methods auto-paginating via `--max-items`. Alternate clients (`AzureOpenAI`
and others) are supported by reflecting the actual surface of the selected
client rather than offering commands that would fail at call time. A drift
gate test enumerates the SDK surface, asserts every endpoint method has a
registered command, and checks the discovered count against a committed
baseline file — so both additions and removals are caught by CI.

## Consequences

An `openai` SDK upgrade that adds or removes an endpoint fails CI until the
baseline is deliberately updated, which is what makes the "no gaps" claim
enforced rather than aspirational. The endpoint count itself is intentionally
not written down in prose anywhere, since a hardcoded number goes stale after
the next SDK release. Risk is low — the drift gate makes a silent gap
mechanically impossible.
